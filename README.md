# 墨迹 · 博客系统（含管理后台）

一个**零依赖、零构建**的博客系统：原生 HTML + CSS + JavaScript 写成的静态页面，
加上两个 Serverless 接口，用 **GitHub 仓库里的一个 JSON 文件当数据库**。

打开页面就能用，不需要 `npm install`，不需要数据库，也不需要服务器常驻。

> **为什么不是纯前端了？**
> 早期版本把内容全部存在浏览器 `localStorage` 里，结果就是在办公室电脑上发布的文章，
> 回家打开同一个网址却看不到 —— 因为数据从来没有离开过那台电脑。
> 现在已发布的文章会同步到云端仓库，**任何设备打开同一个网址看到的都是同一批内容**。

---

## 数据放在哪

| 内容 | 存放位置 | 换设备能看到吗 |
| --- | --- | --- |
| 已发布的文章 | GitHub 仓库里的 `data/blog-db.json` | ✅ 能 |
| 站点设置、分类、标签 | 同上 | ✅ 能 |
| 草稿 | 只在本机 `localStorage` | ❌ 不能（刻意如此） |
| 登录态 | 本机 `sessionStorage` | — |

草稿之所以不上传，是因为 `data/blog-db.json` 会跟着站点一起被静态托管，
任何访客都能直接下载它。只放已发布的内容，就不存在草稿泄漏的问题。
想让别的设备看到，把文章设为「已发布」再保存即可。

## 部署到 Vercel

### 1. 拿到一个 GitHub Token

打开 <https://github.com/settings/personal-access-tokens/new> 创建一个
**Fine-grained token**：

- **Repository access** → 选中你这个博客仓库
- **Permissions** → `Contents` 设为 **Read and write**
- 生成后把 token 复制下来（只显示一次）

### 2. 在 Vercel 里配置环境变量

项目 → **Settings → Environment Variables**，添加：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `GITHUB_TOKEN` | ✅ | 上一步的 token |
| `ADMIN_PASSWORD` | ✅ | 后台密码。**不设置就会退回默认密码 `admin123`，任何人都能改你的博客** |
| `GITHUB_REPO` | — | `owner/repo`。留空时自动用当前站点所在仓库 |
| `GITHUB_BRANCH` | — | 数据文件所在分支。**建议留空**，会自动使用仓库的默认分支 |
| `GITHUB_DATA_PATH` | — | 默认 `data/blog-db.json` |
| `AUTH_SECRET` | — | 登录令牌签名密钥。留空则复用 `ADMIN_PASSWORD` |
| `AI_BASE_URL` | — | AI 助手用的 OpenAI 兼容接口根地址，填到 `/v1` 即可 |
| `AI_API_KEY` | — | 模型服务商密钥，只存在服务端 |
| `AI_MODEL` | — | 模型名，例如 `deepseek-chat`、`gpt-4o-mini` |

> AI 的三个变量**要么都填、要么都不填**。都填了后台编辑器里才会出现 AI 助手；
> 没填也不会报错，只是按钮点了会提示「AI 功能尚未配置」。

保存后到 **Deployments → 最新一次部署 → Redeploy**，让环境变量生效。

### 3. 打开后台，把老内容搬上去

访问 `/admin.html` 登录。如果云端还没有数据文件，登录成功后会自动把**本机已有的
文章**整体提交上去，这就是老版本内容的迁移路径。之后在任何电脑上打开，
看到的都是同一批文章。

> 每次保存都会在仓库里产生一个 commit，因此也会触发一次 Vercel 重新部署。
> 数据是运行时通过 `/api/db` 读的，所以**站点立刻就是最新的**，重新部署只是额外开销。
> 不想让它频繁部署，可以把数据放到一个单独的仓库（比如 `your-name/blog-data`），
> 然后用 `GITHUB_REPO` 指过去；如果内容不想公开，那个仓库设为私有即可。

## 本地开发

直接双击 `index.html` 也能跑：`/api` 不存在时会自动降级成**纯本地模式**，
数据只写进 `localStorage`，功能齐全，只是不会同步到别的设备。

想连真实接口调试，用 Vercel CLI：

```bash
cp .env.example .env.local   # 填入 GITHUB_TOKEN 和 ADMIN_PASSWORD
vercel dev
```

│   └── ai.js           提示词、OpenAI 兼容调用、输出清洗
├── css/
│   ├── style.css       前台样式（浅色 / 深色双主题）
│   └── admin.css       后台样式
├── js/
│   ├── store.js        数据层：本地缓存 + 云端同步、统计、导入导出
│   ├── markdown.js     零依赖 Markdown 渲染器（含 XSS 防护）
│   ├── app.js          前台：路由与视图
│   └── admin.js        后台：登录、文章管理、编辑器、设置、备份
├── data/

分层很清楚：**store.js 不认识 DOM，markdown.js 不认识数据**，
视图层只调用 `window.Blog` 和 `window.Markdown`，接口层只认 HTTP。

## 管理后台

访问 `/admin.html`。

| 项 | 值 |
| --- | --- |
| 密码 | 环境变量 `ADMIN_PASSWORD`，未设置时为 `admin123` |
| 修改密码 | 改环境变量后重新部署（页面上有步骤说明） |
| 登录态 | 12 小时有效的签名令牌，存在 `sessionStorage`，关掉标签页即失效 |

后台功能：

- **仪表盘** —— 文章数、草稿数、分类标签数、累计阅读、总字数、最近更新，以及同步状态
- **文章管理** —— 搜索、按状态/分类筛选、分页；一键发布 / 下架 / 删除
- **写文章** —— 左侧 Markdown、右侧实时预览；标题、slug、分类、标签、封面、摘要、状态
- **AI 助手** —— 生成正文、生成标题、一键排版（需配置 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`）
- **分类与标签** —— 新增 / 重命名 / 删除（重命名会同步更新所有文章）
- **站点设置** —— 站名、副标题、作者、描述、页脚、备案号、每页文章数、默认主题
- **数据备份** —— 导出 / 导入 JSON，一键恢复演示数据
- **密码与同步** —— 同步状态诊断、从云端重新拉取
- **快捷键** —— 编辑器内 `Ctrl/Cmd + S` 保存

后台顶部会一直显示同步状态，**任何会导致「保存了但别的电脑看不到」的情况都会明确提示**，
不会出现界面报「已发布」而实际没写进云端的情况。

### 编辑器小细节

- 新建文章时会自动把内容存为**本地草稿**，误关页面后回来可恢复，也可以一键丢弃
- 标题失去焦点时自动生成 slug
- 离开编辑器时若有未保存内容会二次确认
- Markdown 工具栏：标题 / 加粗 / 斜体 / 代码 / 链接 / 列表 / 引用

## AI 助手

后台 **写文章** 页面的正文上方有一块「AI 助手」，三个动作：

| 按钮 | 做什么 |
| --- | --- |
| **生成正文** | 按你填的主题/提纲写一整篇 Markdown。分类、标签、篇幅都会一起带过去 |
| **生成标题** | 根据现有正文（或主题）给 5 个候选，点一下就能换上 |
| **一键排版** | 把乱糟糟的文字整理成规范的 Markdown 结构 |

几个刻意的设计：

- **密钥只在服务端**。`AI_API_KEY` 存在 Vercel 环境变量里，浏览器永远拿不到；
  `/api/ai` 必须带登录令牌才能调用，不会被别人白嫖你的额度。
- **排版不改用词**。提示词里写死了「只调整排版，不得改写、增删或润色任何句子和词语」，
  代码、URL、数字、代码块都要求原样保留。适合把随手记的草稿整理成能发的样子。
- **改动可撤销**。生成正文和一键排版会覆盖输入框，所以：内容非空时会先弹确认，
  改完还会留一个「撤销 AI 改动」按钮（只保留一步，再操作一次就覆盖掉了）。
- **标题不会重复生成**。生成正文后如果标题还空着，会自动再起一个标题并列出候选；
  标题已经填了就不动它。
- 生成正文时不会输出文章大标题，直接从 `##` 小节开始 —— 免得和标题字段里的大标题重复。

### 接哪家模型

任何 **OpenAI 兼容**的 `/chat/completions` 接口都能用，例如 OneAPI、DeepSeek、
通义千问、智谱 GLM、Kimi、OpenRouter、本地 Ollama：

```
AI_BASE_URL=https://api.deepseek.com/v1     # 填到 /v1 就行，会自动补 /chat/completions
AI_API_KEY=sk-xxxxxxxx
AI_MODEL=deepseek-chat
```

### 注意

- 生成一篇 1200 字的文章通常要 10–30 秒。Vercel 上这个函数的上限是 60 秒，
  已经在 `vercel.json` 里设成 `maxDuration: 60`；如果你的套餐不允许，把它调小即可。
- 接口是**非流式**的：等模型写完一次性返回，期间按钮会禁用并显示进度。
- 一键排版的输入上限是 2 万字符，超了会提示你分段处理（宁可报错也不截断你的文章）。
- 模型会写错事实。它是个起稿工具，发布前请自己过一遍。

## Markdown 支持

渲染器是手写的，只依赖字符串操作。

| 语法 | 说明 |
| --- | --- |
| `#` ~ `######` | 标题，自动生成锚点 id |
| 空行分段 | 段内换行渲染为 `<br>` |
| `**粗体**` `*斜体*` `~~删除线~~` | 行内样式 |
| `` `行内代码` `` | 单行代码 |
| ` ```lang ` … ` ``` ` | 围栏代码块，带语言标签 |
| `-` / `1.` | 无序、有序列表，支持缩进嵌套 |
| `- [x]` / `- [ ]` | 任务列表 |
| `>` | 引用，支持递归嵌套 |
| `\| a \| b \|` | 表格，支持 `:---:` 左右居中对齐 |
| `---` | 分割线 |
| `[文字](url)` `![alt](url)` | 链接与图片（外链自动 `target="_blank"`） |

**安全处理**：所有文本先整体做 HTML 转义再拼接标签；链接协议过滤掉
`javascript:` / `vbscript:` 以及非图片的 `data:`。所以文章内容里的
`<script>` 只会以文本形式显示。

## 同步是怎么做的

数据层刻意保留了**同步的读接口**（`listPosts` / `getPost` / `stats` …），
它们只读内存，所以两个视图的渲染代码几乎没动；只有写操作返回 Promise。

```
页面启动 → Blog.ready()
             ├─ GET /api/db  →  有云端数据？合并进来
             ├─ 接口不可用？ →  退回本机 localStorage，页面照常渲染并提示
             └─ 云端是空的？ →  保留本机内容，登录后自动整体推上去

保存文章 → Blog.savePost()
             ├─ 先改内存 + 写 localStorage（同步、立刻见效）
             └─ 再 PUT /api/db（带 sha），成功才算「已发布」
```

几个关键取舍：

1. **并发控制**：写入时带上读到的 `sha`。如果期间有别的设备写过，GitHub 会拒绝，
   接口返回 409 并提示「云端已被其他设备修改」，而不是悄悄覆盖别人的改动。
2. **绝不谎报成功**：`commit()` 永远 resolve，用 `{ok, synced}` 告诉界面到底同步成功没有。
   失败时页面提示「本机已生效，云端未同步」，顶部还有常驻提示条。
3. **不丢稿**：云端文档去掉草稿后再写入；合并时本机草稿一律保留。
4. **阅读量不推送**：访客每看一篇文章就提交一次 commit 显然不合理，
   所以阅读量只在本机累加，后台下次保存时顺带写上去。
5. **接口不缓存**：`/api/db` 明确返回 `Cache-Control: no-store`，
   否则 CDN 会把旧数据缓存住，又会变成「换台电脑看不到新文章」。

## 常见问题

**Q：忘了后台密码怎么办？**
A：密码在 Vercel 的环境变量里，去 Settings → Environment Variables 改掉，
重新部署即可。它不受浏览器数据影响。

**Q：能多人协作吗？**
A：可以多人登录（共用同一个密码），但写入是「整份文档覆盖 + sha 校验」，
两个人同时编辑会有一方收到「云端已被其他设备修改」的提示，需要刷新后重做。
单人使用不需要关心这一点。

**Q：后台界面报「云端没有连上」？**
A：多半是环境变量没配好或者没重新部署。看一下提示条里的具体报错：
Token 权限不足是 403，仓库或分支写错是 404。也可以去后台「密码与同步」页看状态。

**Q：草稿会同步吗？**
A：不会，草稿只在本机。原因见上面「数据放在哪」一节。

**Q：文章里的图片怎么处理？**
A：填外链 URL。封面和图床都只存 URL，不存二进制。

**Q：`data/blog-db.json` 别人能下载到吗？**
A：能 —— 它和站点一起被托管。所以里面只有本来就对外公开的已发布内容，
没有草稿、没有密码。
